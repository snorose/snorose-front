# Toast 인터페이스 교체 검증

```bash
npm run test:toast-migration
```

검사 중 하나라도 실패하면 명령이 실패한다. 외부 서버나 로그인 계정 없이 실행한다.

## 검증 범위

| 검사                            | 확인하는 내용                                                                                                                                                                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 고정 커밋 `3ee33ff5`와 AST 비교 | 제품 JS/TS 파일 전체의 구조를 비교하고, 41개 파일의 145개 호출에서 메시지·variant·주변 분기 보존을 확인한다. 별칭을 추적하고 해석하지 못하는 사용 방식은 실패시킨다.                             |
| 검증기 테스트                   | 각 실제 호출에서 메시지 변경·variant 변경·호출 삭제를 만든 435개 사례를 감지하는지 확인한다.                                                                                                     |
| `useToast.test.jsx`             | 실제 hook/Provider/Toast로 유형별 표시, 자동 닫힘, 중복 제거, 교체 시 타이머 갱신을 확인한다.                                                                                                    |
| `useToast.migration.test.jsx`   | 실제 화면 또는 hook 소비자의 이벤트부터 mutation·라우터·Toast 표시까지 연결한다. 비밀번호 변경 성공/실패, 댓글 검증/저장/실패, 시험후기 삭제/다운로드 실패, 알림 설정 실패/권한 안내를 확인한다. |
| `AttachmentBar.test.jsx`        | 새 mock 인터페이스에서 기존 파일 첨부 정책과 오류 안내 호출이 유지되는지 확인한다.                                                                                                               |

## 통합 테스트의 경계

- `useToast`, ToastProvider, Toast, QueryClient, useMutation, MemoryRouter는 실제 구현을 사용한다.
- 댓글 입력, 비밀번호 변경, 다운로드, 알림 설정은 실제 컴포넌트를 사용한다. 삭제 hook에는 클릭 가능한 소비자 컴포넌트를 연결한다.
- API 함수의 응답과 브라우저 푸시 권한을 mock으로 통제한다. Toast 함수 자체를 spy/mock으로 대체하지 않는다.
- barrel export는 필요한 실제 모듈만 불러온다. 관계없는 앱 바와 인증 정보 갱신, 설치되지 않은 아이콘 패키지의 그림은 대체한다.
- 메시지의 실제 DOM 표시와 유형, 저장 요청 유무, 입력 보존, 페이지 이동, 설정 복구를 확인한다. 이 테스트는 jsdom 통합 테스트이며 실제 브라우저 E2E 테스트는 아니다.

## 동작 보존의 예외

142개 호출은 기존 메시지와 유형을 보존한다. 아래 3개는 검사에서 별도로 보고하는 동작 변경이다.

1. `ReviewDownload`: 기본 안내 유형 → 오류 유형. 작업 시작 전에 사용자가 변경한 내용이다.
2. `useDeleteExamReviewHandler`: 기본 안내 유형 → 오류 유형. 작업 시작 전에 사용자가 변경한 내용이다.
3. `AlertSettingPage`: 잘못된 `toast(error.message)` 호출을 `toast.error(error.message)`로 수정했다.

세 경우 모두 실제 소비자 통합 테스트에서 오류 메시지와 오류 유형을 확인한다.

AST 비교는 이번 교체 전용 검사다. 향후 기능 변경으로 호출이나 코드가 추가되면 의도적으로 실패할 수 있으므로, 통과시키기 위해 기준 커밋이나 기대 개수를 임의로 변경하지 않는다. 통합/회귀 테스트는 이후에도 유지한다.

전체 앱의 빌드·타입 검사와 실제 브라우저 실행을 대신하지 않는다. 현재 전체 타입 검사는 기존 `NewButton.jsx`의 TypeScript 문법 오류로 막혀 있으며, 전체 테스트 중 별도 3개 묶음은 아이콘 모듈을 찾지 못한다. 이 명령의 통과를 전체 앱 검사 통과로 해석하지 않는다.
